Business Gateway

Take payments on your own website. Your server creates an order, you send the customer to our checkout page, and we tell you when they've paid.

Demo gateway. No real money moves, no bank is contacted and no card is charged. Do not ask real customers for real card numbers. Taking real payments in India needs an RBI-licensed aggregator — see the last section.

Your credentials

Create a gateway in the LSP-Pay app under Business gateway. You get two values:

Key IDlsp_test_… — public. Safe to put in a URL or a page.
Secretlsps_… — private, like a password. Shown once, stored only as a hash.
The secret must never reach a browser. Not in your HTML, not in your JavaScript, not in a mobile app, not committed to GitHub. Anyone who has it can create orders in your name, read your customers' email addresses, and mark payments as collected. Keep it in a server environment variable. If it leaks, roll it in the app — the old one dies instantly.

1. Create an order

From your server, never the browser. Authenticate with HTTP Basic: username is your key ID, password is your secret.

curl -X POST https://YOUR-APP.onrender.com/api/v1/orders \
  -u "lsp_test_xxxxx:lsps_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 499,
    "description": "Blue cotton shirt, size M",
    "reference": "your-order-8821",
    "customer_email": "buyer@example.com"
  }'

2. Send the customer to checkout

Redirect them to checkoutUrl, or open it in a new tab. The page carries your business name, your logo and your chosen theme, and offers the methods you switched on. Links stop working after 30 minutes.

3. Find out if they paid

Two ways. Use the webhook for speed and polling as a safety net — do both if the payment matters.

Webhook

Set an https URL in the app. We POST JSON to it on every result, with an X-LSP-Signature header: HMAC-SHA256 of the exact raw body, keyed with your webhook secret. Always verify it, or anyone who guesses your URL can fake a payment.

const crypto = require('crypto');

app.post('/lsp-webhook',
  express.raw({ type: 'application/json' }),   // raw body, not parsed
  (req, res) => {
    const expected = crypto
      .createHmac('sha256', process.env.LSP_WEBHOOK_SECRET)
      .update(req.body)
      .digest('hex');

    const given = req.get('X-LSP-Signature') || '';
    const ok = expected.length === given.length &&
      crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(given));

    if (!ok) return res.sendStatus(400);

    const { event, order } = JSON.parse(req.body);
    if (event === 'order.paid') {
      // Ship the goods. Look up order.reference to find your own record.
    }
    res.sendStatus(200);
  });

Polling

curl https://YOUR-APP.onrender.com/api/v1/orders/ord_xxx \
  -u "lsp_test_xxxxx:lsps_xxxxx"

Trust status, never the customer's browser. A customer landing on your success page proves nothing — only the API does.

Emails

Four emails go out through Resend, all carrying your business name and logo.

Payment linkTo the customer, when you create an order with "notify": true and a customer_email. Contains a Pay button.
ReceiptTo the customer, automatically, once they pay.
Payment receivedTo you, whenever money lands. Switch it off under gateway settings.
Gift cardTo the recipient, when someone buys one in the app.

Emailing a payment link

Same as Razorpay's Payment Links: no website needed, the customer pays from their inbox.

curl -X POST https://YOUR-APP.onrender.com/api/v1/orders \
  -u "lsp_test_xxxxx:lsps_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 449,
    "description": "Filter coffee, 250g",
    "customer_email": "buyer@example.com",
    "notify": true,
    "note": "Thanks for your order!"
  }'

The response carries emailed: true when it went out, or emailNote explaining why it didn't. To send it again later:

curl -X POST https://YOUR-APP.onrender.com/api/v1/orders/ord_xxx/notify \
  -u "lsp_test_xxxxx:lsps_xxxxx" \
  -H "Content-Type: application/json" -d '{}'
Resend's sending limits apply. Until you verify your own domain, Resend only delivers to the address you signed up with — every other recipient silently fails. Add a domain in Resend and set MAIL_FROM before emailing real customers.

Refunds

Full or partial, as many times as you like until the order is used up. The money comes out of your LSP-Pay wallet, so it fails if you've already spent it — same as a real gateway with an empty settlement account.

# everything
curl -X POST https://YOUR-APP.onrender.com/api/v1/orders/ord_xxx/refund \
  -u "lsp_test_xxxxx:lsps_xxxxx" -H "Content-Type: application/json" -d '{}'

# part of it
curl -X POST https://YOUR-APP.onrender.com/api/v1/orders/ord_xxx/refund \
  -u "lsp_test_xxxxx:lsps_xxxxx" -H "Content-Type: application/json" \
  -d '{"amount": 200, "reason": "Item out of stock"}'

If the customer paid from an LSP-Pay wallet, the refund lands back in that same wallet. The customer is emailed either way, a order.refunded webhook fires, and GET /api/v1/orders/:id/refunds lists them. An order becomes refunded once the full amount is back. Refunding from the app works too: Business gateway → tap Refund next to any paid order.

Shareable payment links

PayU and Razorpay both call these payment pages: one URL you reuse forever instead of an API call per customer. Put it in a bio, a WhatsApp message or a printed QR code. Each visit mints its own order, so two people paying at once never collide.

curl -X POST https://YOUR-APP.onrender.com/api/v1/links \
  -u "lsp_test_xxxxx:lsps_xxxxx" -H "Content-Type: application/json" \
  -d '{"title": "Coffee subscription", "amount": 250, "usageLimit": 100, "expiresInDays": 30}'

Leave amount out and the payer names their own figure — useful for tips and donations. usageLimit and expiresInDays are both optional. POST /api/v1/links/:id/deactivate switches one off, and GET /api/v1/links lists them. You can also make them in the app with no key at all: Business gateway → Shareable payment links.

Idempotency

Send an Idempotency-Key header when creating an order. If the request is retried — dropped connection, impatient customer, a queue redelivering — you get the original order back instead of a second charge.

curl -X POST https://YOUR-APP.onrender.com/api/v1/orders \
  -u "lsp_test_xxxxx:lsps_xxxxx" \
  -H "Idempotency-Key: your-cart-8821" \
  -H "Content-Type: application/json" -d '{"amount": 499}'

Use something tied to the thing being bought, like your own cart or invoice id — not a random value, which would defeat the point.

Webhook retries

If your server doesn't answer 2xx, we retry after 10 seconds, then 1 minute, 5 minutes, 30 minutes and 2 hours, then stop. Each attempt carries X-LSP-Delivery (same id every time) and X-LSP-Attempt. Because a retry can arrive twice, make your handler idempotent — check whether you've already shipped before shipping again.

What can still go wrong

The gateway blocks double payment, replayed links, expired links, tampered webhooks and cross-merchant order access. What it cannot do is make an unlicensed business legal, or survive its own secret being pasted into a web page. Two rules carry most of the risk:

  • Never trust the browser. Confirm every payment against the API or a verified webhook before you ship anything.
  • Never publish the secret. If it appears in any file a customer can download, roll it immediately.

Going live

This is a demo. Collecting real money in India means being an RBI-authorised payment aggregator or working through one — Razorpay, Cashfree, PayU and Stripe India all do this and handle the licensing, KYC and settlement for you. Their sandboxes are free. Build against this gateway to shape your checkout, then swap the two calls in src/cards.js and the order routes for theirs when you're ready.
